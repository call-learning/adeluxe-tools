# adeluxe-tools

This draft contains three parts:

- `installer/`: a Composer plugin (`adeluxe-tools/adeluxe-installer`).
- `package/`: the reusable Adeluxe source package (`adeluxe-tools/moodle-adeluxe`).
- `example-plugin/`: a Moodle plugin root showing selective module installation.

## Selective installation

The consuming Moodle plugin decides what it wants:

```json
"extra": {
  "adeluxe": {
    "component": "mod_example",
    "target": ".",
    "modules": ["repository", "modal"]
  }
}
```

If it only wants repository helpers:

```json
"modules": ["repository"]
```

The Adeluxe package is stored under `.adeluxe/packages/` rather than the normal `vendor/` path, while selected source is materialised into Moodle-native locations:

- PHP -> `classes/local/adeluxe/...`
- AMD source -> `amd/src/local/adeluxe/...`
- Mustache -> `templates/local/adeluxe/...`
- strings -> merged into `lang/en/<component>.php` between generated markers

`__COMPONENT__` is replaced with the target Moodle component, so the same Adeluxe source can become either:

- `mod_example\\local\\adeluxe\\repository\\base_repository`
- `local_whatever\\local\\adeluxe\\repository\\base_repository`

and AMD/template names likewise become component-local.

## Generated file ownership

`.adeluxe/generated.json` records files generated by Adeluxe. When a module is removed from the configured module list, files previously generated for that module are deleted without touching unrelated plugin files.

## Suggested development workflow

Treat `adeluxe-tools/moodle-adeluxe` as a development/build dependency and commit the materialised Moodle source to the plugin repository. The distributed Moodle plugin then has no runtime dependency on Composer or another Moodle plugin.

## Important draft limitations

This is deliberately a first implementation rather than a production release. Before publishing it I would add:

1. File hashes so Adeluxe refuses to overwrite a generated file that a developer modified locally.
2. Per-language language resources rather than English only.
3. Module dependencies, e.g. `datatable` can declare `requires: [repository]`.
4. Conflict detection when two Adeluxe packages generate the same target path/string key.
5. A `composer adeluxe:sync` command in addition to automatic sync after autoload generation.
6. Tests using Composer's test utilities and temporary Moodle-plugin fixtures.
7. Optional groups/presets such as `forms`, `ui`, or `all`, without making `all` the default.
